# 用户明确要求实测时

选择能覆盖本次行为的最小验证。优先复用项目已有测试和已绑定该项目的会话。先确定项目路径、构建目标与运行环境；设备、权限、会话或数据缺失时，按报告协议记录具体未覆盖项。普通开发和静态评审不需要运行这里的步骤。

## 复用现有自动化会话

如项目使用 `miniprogram-automator`，使用项目已有依赖及明确对应目标项目的自动化 WebSocket 端点，通过 `automator.connect({ wsEndpoint })` 连接。IDE 的 HTTP 服务端口、端口号惯例和单纯的 TCP 监听都不足以确定该端点及项目身份。缺少项目绑定证据时，停在连接前。连接后可先只读核对页面/构建标识；不符即 `disconnect()`。退出时在 `finally` 断开本次连接，保留用户已打开的开发者工具和权限设置。

涉及改数据的验证应使用任务授权且可清理的测试环境、测试记录或项目现有隔离数据。延迟或失败场景可用服务层 fixture，或在专用测试会话用 `mockWxMethod`；后者在 `finally` 中 `await restoreWxMethod(method)`。调试会话已有未知 Mock 或与他人共享时，选择隔离 fixture；还原失败应记录并停止依赖原始行为的后续断言。

## 选与问题匹配的证据

| 目标 | 可观察结果 |
| --- | --- |
| 对齐、异步布局（M-A1、M-A2、M-B1、M-B2） | 固定窗口、滚动位置和测试数据，比较预期同轴的节点和加载前后同一锚点的坐标，记录 CSS 像素差与上下文。由可触达性、设计基线或项目容差判定。锚点位移不要标成 Web Vitals CLS。 |
| 直达返回、冷启动鉴权（M-C4、M-C1） | 现有会话 `reLaunch` 到详情，确认单页栈与返回目的地，可以证明 M-C4。验证 M-C1 需有新应用实例首次启动、权限尚未就绪且受限内容及操作保持关闭的证据。已登录会话的一次 `reLaunch` 只改变页面栈。 |
| 列表一致性（M-C2） | 用隔离测试记录从详情修改后返回，观察列表中的同一条记录并再次进详情。记录测试数据归属及清理结果。 |
| 宿主行为（M-A2、M-A3、M-A4、M-D2） | 涉及软键盘命中区、系统授权框、原生组件叠放和设备安全区时，注明已覆盖的平台与输入方式；需要设备才能证明的行为保留为未验证。 |
