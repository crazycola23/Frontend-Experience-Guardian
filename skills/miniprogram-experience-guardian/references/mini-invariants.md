# 小程序平台规则

按改动选择规则。定位到源码处，说明哪类页面、哪步操作和哪个可观察结果受影响。搜索命中、编码风格和未覆盖场景各自保留其证据性质；只有已经成立的缺陷进入 Findings。各条中的优先级适用于描述的后果，判定以共同报告协议为准。

## A　几何与原生窗口

| 规则 | 何时检查、如何判定 |
| --- | --- |
| M-A1 · P1 | 检查原本应共用对齐线的标题、列表与按钮。沿页面壳与子组件找重复加上的水平留白；通栏横幅、卡片内边距或有意缩进有自己的对齐线。沿用已有间距 token。 |
| M-A2 · P1 | 自定义悬浮 TabBar 或操作栏须使最后一项内容可滚到、可点击。追踪固定栏本体和安全区由谁占高，正文预留应覆盖实际遮挡。系统 TabBar 或已有布局壳承担预留时，避免再次补空白。 |
| M-A3 · P1 | 定制导航栏需让返回控件、标题和微信胶囊在当前窗口共存。追踪窗口信息、胶囊边界或基础组件的实测值，以及无有效测量时的回退。固定的图标尺寸可以保留；将状态栏高度当成设备常量会使导航错位。 |
| M-A4 · P1 | 弹窗打开后，内容本身可滚动且底层不会随手势移动。靠近底边的输入框在键盘弹起时应可见、可确认；按组件的实际滚动容器、键盘避让和关闭后的布局判断。 |

## B　加载稳定性与渲染开销

| 规则 | 何时检查、如何判定 |
| --- | --- |
| M-B1 · P1 | 关注异步区从首次加载、重试到内容出现时，下方可操作元素会否大幅移动或突然被挤走。匹配实际行高的骨架、已占位的容器、保留旧数据均可；已有稳定高度时使用条件渲染也合理。 |
| M-B2 · P1 | 图片尺寸到达前，应为首屏横幅或列表缩略图预留其显示空间。检查父容器、固定比例、元数据或占位样式。只有宽高自适应确实改变外部排版时才记录。 |
| M-B3 · P1 | 追踪滚动、连续触摸、单行更新是否反复跨逻辑层与视图层传递整表或大对象。以更新频率、数据范围、实际渲染依赖为证据，按项更新或按值变化再提交。 |

## C　权限、数据与页面栈

| 规则 | 何时检查、如何判定 |
| --- | --- |
| M-C1 · P0 | 从分享或扫码直接进入受限页面时，权限未就绪期间隐藏受限信息并阻止受限操作，请求失败后保持保护。检查多个入口是否复用同一权威状态。缓存读取如只用于偏好、占位或经过授权层封装，可正常使用。 |
| M-C2 · P0 | 沿编辑成功、返回列表、再次进详情的路径检查是否展示同一条记录的新值。共享状态、失效标记后刷新、事件通知均可。若本次涉及 Mock，核对列表与详情的读写是否落在同一数据源；局部展示常量无须迁移。 |
| M-C3 · P1 | 使用自定义 TabBar 时，连续切换和带参数进入后，选中态应与当前 tab 路由一致。页面生命周期或集中订阅都可承担同步。系统原生 TabBar 已管理自己的选中态。 |
| M-C4 · P0 | 检查可重复压栈的跳转、目标属于 tabBar 的跳转方式、分享或扫码直达的自定义返回动作。微信常规页面栈最多十层。单页栈应有有效出口；深栈按原业务后退。已由路由封装兜底的调用可以直接复用。 |

## D　失败处理与发布边界

| 规则 | 何时检查、如何判定 |
| --- | --- |
| M-D1 · P0 | 查失败、取消和重复点击。加载指示与提交锁在结束后应释放；并发请求需要明确指示器归属。异步提交有重复写入风险时，检查按钮锁或等效的幂等保证；`complete`、`finally` 或统一请求层都可以满足清理语义。 |
| M-D2 · P0 | 必需能力被拒绝后，应能解释原因并有可达的重试、授权或替代入口。区分微信 scope、系统级授权和硬件不可用；按能力选择由用户触发的设置入口或合适的降级。可选功能允许用户直接跳过。 |
| M-D3 · P0 | 影响主包的资源或分包调整，以目标产物的包体统计和适用发布额度判定。对适用 2 MB 主包上限的项目，实际超限才构成发布阻断。单个源码目录大小、接近额度都不能证明超限。 |
