# Web 体验守卫

先按[目标路由](references/guardian-routing.md)确定本次改动服务的应用包和构建目标。此入口处理浏览器及 uni-app H5；同一次变更涉及多个运行时，按目标分别评估。

## 各阶段如何使用

- **规划、原型、实现、修复**：从本次变更挑出有关的 W 规则，静默用于方案、代码和既有验证。普通交付沿用用户要求的格式。
- **常规代码评审**：保留 Matt 工作流的 Standards / Spec 两个轴线。已纳入仓库规范的体验规则归 Standards，明确的验收要求归 Spec。只在对应轴报告有证据的偏差，尊重主评审的输出格式。
- **点名体验评审**：默认只读。按[统一报告契约](references/guardian-contract.md)输出完整报告，区分静态发现、实测结果和尚待验证的影响。修复需要用户明确要求。
- **点名浏览器实测**：只有用户明确要求浏览器操作、截图或运行时验证时，才读取[浏览器探针](references/browser-probe-protocol.md)，按要求的范围执行。仅要求体验评审时使用静态证据。

## 按改动查规则

从[Web 规则表](references/web-invariants.md)选适用编号。W-A1～A3 管布局、视觉与溢出，W-B1～B3 管加载与交互反馈，W-C1～C3 管权限、数据与路由，W-D1～D3 管异常、恢复与键盘对话框。

沿用产品已有的组件、语义和任务路径。优先修复用户无法完成任务、误操作、丢失上下文等可说明后果的问题；保留经授权的业务规则、权限边界与数据含义。
