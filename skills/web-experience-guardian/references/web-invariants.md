# Web 规则与静态证据

从变更的页面、实际调用者和共享布局开始，核对仓库规范及来源需求。规则表给出调查方向。关键词命中只能定位候选，例如图片可从全局 CSS 取得比例，异步状态可由查询库统一清理。只有证据能说明触发条件和用户后果时才列 finding。P0/P1 依统一契约和实际影响判定。

| 编号 | 核查条件和证据 |
| --- | --- |
| W-A1 | 对齐任务相关的内容边、页边距与网格。核对父子容器叠加 padding、混合单位数据、背景条与表头贴边。[留白与信息分层](interface-restraint.md) |
| W-A2 | 让用户首先读到影响决策的状态、数据或操作。审视强度相同的卡片、重复标题、副标题和色彩。警告色附带文字或符号，分类色与状态含义分开。清理界面前追踪被隐藏的入口、数据和规范。[界面取舍](less-is-more.md) |
| W-A3 | 从容器尺寸、换行和滚动归属追踪非预期水平溢出、双重滚动、固定工具栏遮挡。保留宽表格等有意设计的局部滚动。[断点与平台](responsive-platform.md) |
| W-B1 | 检查 loading → loaded 和已加载 → refreshing 分支是否推走阅读锚点。可使用空间预留、骨架、保持已有数据等与内容匹配的实现。[布局稳定](layout-stability.md) |
| W-B2 | 首屏媒体应有可预测的宽高或比例，表格列和重要内容在长文本和跨页数据下仍可读取。避免用截断掩盖用户需要的唯一标识。[表格与阅读](product-ux.md) |
| W-B3 | 核对触控、键盘与指针的可发现性和操作反馈。对能产生重复业务结果的异步提交检查等待状态、请求锁或等效去重，以及失败后的重试。 |
| W-C1 | 路由、菜单和受限动作读取一致的权限状态。检查会话未就绪、权限撤销和角色切换时的受限内容与操作；保留服务端对操作的授权。 |
| W-C2 | 沿真实的列表、详情、编辑和返回路径检查同一记录。成功变更后通过缓存失效、共享状态或重新查询保持一致。演示数据应属于清晰的测试或适配层，业务页面不得将其作为生产事实展示。 |
| W-C3 | 当任务要求可分享、可刷新或可返回时，核对 URL、筛选、分页、标签、滚动恢复及来源导航。核对从搜索、概览或关联记录进入详情后能否回到实际来源。[任务路径](product-ux.md) |
| W-D1 | 追踪会中断本次核心任务的未捕获异常、未处理拒绝、hydration 不一致或未恢复的请求失败。已处理的取消、预期拒绝和无关日志与故障分开记。 |
| W-D2 | 检查异常、取消、过期响应、组件卸载后等待状态和提交锁能否释放。失败应给出恢复入口，保留可恢复的用户输入；finally、框架状态管理等可实现相同保证。 |
| W-D3 | 检查原生或等效控件的标签、焦点可见性、合理的 Escape 行为、模态范围内的键盘导航、关闭后的焦点与滚动恢复。[无障碍与本地化](accessibility-i18n.md) |

## 原生边距与产品惯例

审查 W-A1 时，分别检查绘制背景或边框的容器，以及浏览器原生排版。字号 12–14 px 的小型标签、色带和表头可用旧守卫的起点 **横向 8 px、纵向 4 px**，并对照项目 token。圆角胶囊从曲线量净距。原生 `fieldset > legend` 可能坐在边框凹口，`caption` 在表格框外；需要与组内字段对齐时保留语义，检查实际位置和内边距。

高密度工作台的滚动归属、表格列宽、分页密度、状态色分工以及跨实体返回，在上方按主题链接的旧规则中有具体实例。以适用的业务场景和既有交互约定为依据。多轮改稿和交付时可查[收尾规则](finalization.md)。守卫维护者验证触发与判定时可用[既有评审场景](../evals/README.md)。
