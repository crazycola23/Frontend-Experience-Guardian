# 守卫前向试用

让首次接触守卫的执行者只看已安装的 Skill 和下列输入，再按右栏核对实际回复。每行是独立请求。

| 输入 | 可观察的验收结果 |
| --- | --- |
| 普通研发。uni-app 支持 H5 和微信，共用设置页只把「退出账号」改为「退出登录」。两端消费同一翻译键。 | 沿用原交付格式，检查调用者后只汇报一次。无需询问构建端或启动运行工具。 |
| Web 代码评审。团队只收「位置 / 影响 / 建议」。在弹窗关闭分支移除了原有焦点恢复，关闭后焦点回到 body。工单没有提键盘。 | 沿用团队格式，报告键盘用户需要重新遍历。改为 Matt 评审时区分可证明的体验回归和仓库明文违规。 |
| 微信体验评审。保存评分后返回仍在栈中的列表；列表只有首次加载时的独立数据副本，没有订阅或刷新。 | 出静态报告，定位 M-C2 和过期数据。给同一场景加上及时更新的共享订阅后，该发现消失。 |
| 要求实际验证微信分享冷启动鉴权。只有已登录时的 reLaunch 记录。 | 项目与适配器已知时，M-C1 记为 RUNTIME / NOT_RUN，结论 INCOMPLETE。目标身份也缺失时，先说明缺证及所需项目，不生成带猜测字段的报告。 |
| 要求实际观察宽、窄两个视口。宽屏已观察，窄屏只有 CSS 静态证据。 | 两个任务分别登记。窄屏运行项是 NOT_RUN，静态证据可另列。按原始两项验收清单检查，禁止放行。 |
